# 朝ブリーフの受け渡し形式（IS-03）

## 方式（2026-10-02 ユーザー決定）
1. 毎朝、Web版Work が当日情報を Google Drive「週間タスクボード」フォルダ直下の `朝情報.md` へ上書き保存する（Obsidian Vault「週間タスク」フォルダの外。日次経路ではObsidianを使わない）。
2. 予約「【週間タスク】日次AI現在地巡回」（Desktop版Work、1本のまま）の後段が、`朝情報.md`、`AI案件_日次現在地.md`（同じ予約の前段の結果。docs/AI_DAILY_FORMAT.md）、Sheets「タスク」シート（今週の確定タスク・状態・実績・タスクID）を読み、下記JSONを1本だけ作って Google Drive「週間タスクボード」フォルダ直下の `朝ブリーフ.json` へ上書き保存する（追加実装 v1.1。AI現在地用の別JSONは作らない。2026-10-22 追加改修指示書 JSON手渡し自動化 v1.1：画面に出さない。指示文は docs/prompts/project_morning_brief.md）。
3. GAS の時間トリガー（1時間おき。関数 importBriefFromDrive、src/Import.js）が `朝ブリーフ.json` を読み、種別（「日付」＋「今日の一言」）を判別し、下記の検証に合格した当日分を Sheets「朝ブリーフ」シートへ追記保存し、AI案件現在地を同期する（保存・同期・履歴は貼付保存と同じ saveMorningBrief の決まり。docs/DB_SCHEMA.md）。ユーザーは画面を開くだけで見られる（JSONに触れない）。
   - 取り込まない場合：今日の朝ブリーフがすでに保存済み（手動取込を含む。ユーザーの保存を上書きしない）、ファイルがない、同じ名前のファイルが複数ある、日付が今日ではない、JSONとして読めない、検証に合格しない、中身が週間分析のJSON。結果と理由はスクリプトのプロパティに記録し、朝ブリーフ画面に表示する（失敗は赤枠。前日の内容や前日の記録を今日の分として見せない）。
   - 文字の補正：JSONとして読めない場合だけ、先頭の BOM・コードブロック記号（```）・Markdown表示で付いた「\」（例：TASK\_CURRENT）を外して1回だけ読み直す。「\\」の組（Windowsの場所）や「\n」などは変えない。それでも読めなければ取込失敗（推測で補わない）。
4. 貼付欄は「手動取込（非常用）」として朝ブリーフ画面に残す。自動取込が止まったときだけ使う（貼り付けて「読み込む」→ 確かめて「保存」）。

## JSON形式
```json
{
  "日付": "2026-10-02",
  "今日の一言": "今日の短い見立て（文章）",
  "今日の流れ": ["09:00 全体朝礼", "14:30 移動（本社→福岡）"],
  "今日優先すること": ["..."],
  "気にかけておきたいこと": ["要確認：...", "..."],
  "もう片づいていること": ["..."],
  "未完了・持越し": ["..."],
  "AI案件現在地": [
    {"taskId": "T-...", "案件名": "営業AIメモ", "取得結果": "確認済み", "現在地": "P2-08 §14-1 完了、§14-2 着手", "取得日時": "2026-10-06 07:30", "内容": ""},
    {"taskId": "T-...", "案件名": "機械販売事例アプリ", "取得結果": "不一致", "現在地": "", "取得日時": "2026-10-06 07:30", "内容": "TASK_CURRENT.mdとDrive正本の方式が一致しない"}
  ]
}
```

| キー | 必須 | 値 | IS-03 の生成内容 |
|---|---|---|---|
| 日付 | 必須 | 対象日 `yyyy-MM-dd` | — |
| 今日の一言 | 必須 | 文字列 | 短い見立て |
| 今日の流れ | 必須 | 文字列の配列（空配列可） | 予定 |
| 今日優先すること | 必須 | 文字列の配列（空配列可） | 今日やること・要対応 |
| 気にかけておきたいこと | 必須 | 文字列の配列（空配列可） | 注意 |
| もう片づいていること | 必須 | 文字列の配列（空配列可） | — |
| 未完了・持越し | 必須 | 文字列の配列（空配列可） | 持越し/停滞 |
| AI案件現在地 | 任意 | 配列（追加実装 v1.1）。今週のAI案件ごとに1件 | 日次AI現在地 |
| AI案件現在地[].案件キー | 任意 | AI案件_日次現在地.md の「確認元 - TASK_CURRENT.md」の場所（追加改修④③）。あれば今週の「タスク」の案件キーで突き合わせる | 突合キー（優先） |
| AI案件現在地[].taskId | 任意 | Sheets「タスク」のタスクID（今週の行）。案件キーが無い場合に使う。案件キーと別の行を指す場合は同期しない | 突合キー |
| AI案件現在地[].案件名 | 任意 | 表示用。突合には使わない | — |
| AI案件現在地[].取得結果 | 必須 | 確認済み／要確認／不一致／取得失敗／チャット未確認 | — |
| AI案件現在地[].現在地 | 確認済みのとき必須 | 確認できた現在地（推測で補わない） | — |
| AI案件現在地[].取得日時 | 確認済みのとき必須 | `yyyy-MM-dd HH:mm`（日次AI現在地ファイルの取得日時） | — |
| AI案件現在地[].内容 | 任意 | 確認済み以外の理由（不一致の内容など） | — |

見出しは機能仕様書 v1.7 §3 の6項目。形式に合わない場合、画面（手動取込）はエラー枠に理由を表示し、自動取込は取込失敗と理由を記録して、どちらも保存しない。
JSONの文字列では「\」を「\\」と書く（Windowsの場所。例："C:\\Users\\inamori240\\Documents\\sample-project\\tasks\\TASK_CURRENT.md"）。「案件キー」は TASK_CURRENT.md の場所だけで、説明・取得経路などは「内容」に書く（2026-10-14。説明が付いた案件キーは画面で受け付けない）。
同じ日付で再保存した場合は追記し、画面はその日付の最新を表示する（既存行は上書きしない）。

### AI案件現在地の扱い（追加実装 v1.1、追加改修④③）
- 突き合わせ：案件キーがある項目は、今週の「タスク」行（削除済みを除く、種別AI案件）のうち案件キーが一致する1行。taskId も書かれていて別の行を指す場合は同期しない。案件キーが無い項目は taskId で突き合わせる。タスク名では突き合わせない。
- 今週の行がまだ無い場合（月曜、週間分析の確定前など）：案件キーが一致する、いちばん新しい前の週の行に記録する（その週に同じ案件キーの行が複数ある場合と、今週の同じ案件キーの行を削除した場合は記録しない）。週間分析を確定して今週の行を作ると、最新取得が今週の行へ写り、月曜朝に確認済みになった現在地は週間分析の値より優先して今週の行の「AI案件現在地」になる（2026-10-11 ユーザー決定「最新でいい」）。同期結果には記録した週を表示する。
- 記録：取得日時が朝ブリーフの日付と同じものだけ。すべての取得結果を、その行の「最新取得日時」「最新取得結果」（確認済み以外は「区分：内容」）「最新取得現在地」に記録する。
- 「確認済み」のときだけ「AI案件現在地」と「現在地確認日時」も更新する。要確認／不一致／取得失敗／チャット未確認は「AI案件現在地」を上書きしない（前回の値を保持し、未確認の最新取得として区別して表示する）。前回と同じ値は書き換えない。変更は履歴に残る。
- 画面表示：現在地には「確認済み MM/DD HH:mm」または「日次で未確認」（週間分析などの値）を添える。確認済みより新しい未確認の取得は「最新取得 MM/DD HH:mm：（現在地）［区分］」として別の行に出す。保存後の同期結果は「確認済みの現在地を記録」「未確認として最新取得に記録（現在地は前回のまま）」「更新しない（理由）」に分けて表示する。
- 確認済み以外の案件は「気にかけておきたいこと」にも「区分：案件名／内容」で書く。
- AI案件現在地は「朝ブリーフ」シートには保存しない（最新＝「タスク」、過去＝「履歴」）。
- 週間タスク画面から手動追加したAI案件（追加実装 v1.2。持越し後の行を含む）は、案件キーが無い場合、taskId が一致しても同期しない（ローカルAI案件との安全な対応が成立していないため）。案件キーが設定されていれば、案件キーで同期する。同期結果に理由を表示する。
- 「AI案件現在地」の無い従来のJSONもそのまま保存できる。
