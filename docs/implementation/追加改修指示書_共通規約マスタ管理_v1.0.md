# 追加改修指示書 — 共通規約のマスタ管理（正本リポジトリの新設と写しの運用）

全案件共通　追加改修指示書 v1.0（2026-10-23 ユーザー承認）

> 位置づけ：週間タスク・朝ブリーフ案件の実装とは独立した、共通規約2文書（ルールブック.md・GitHubリポジトリ標準規約.md）の運用改修。各案件の正本・コード・データは変更しない。

## 0. 既存規約との関係
- 規約§7「共通規約の改訂」は、マスタの置き場を定めておらず、自動同期を実証済みとしない。本書はこの未定義部分を「専用リポジトリをマスタとし、配布は都度指示・一致確認」で確定する。自動同期は引き続き行わない（§7維持）。
- 規約§5「派生名を乱立させず本文とGit履歴で版を管理」「既存正式名称は無断改名しない」に従い、2文書のファイル名は変えない。

## 1. 目的（ユーザー承認 2026-10-23）
- マスタが無く、改訂のたびに各リポジトリへ個別配布して食い違いが出る問題（2026-10-23 の改訂で実際に発生：5リポジトリ個別配布、1件は独自版と競合）を解消する。
- 「どれが正か」と「各リポジトリの写しが最新か」を機械で検査できる状態にする。

## 2. 方式（確定事項）
- 新設リポジトリ：xxxinakenxxx-hash/standards（非公開）。中身は ルールブック.md・GitHubリポジトリ標準規約.md の2文書と README.md（改訂・配布の手順）。この2文書の正本はここだけとする。
- 初版の内容：Weekly-Tasks の現行版（規約3-1・工程完了とmainへの反映の節を含む最新）をそのまま正本の初版とする。
- 各案件リポジトリの2文書は「写し」とし、冒頭に次の2行を入れる：
  - 正本：https://github.com/xxxinakenxxx-hash/standards
  - 写しの元：standards のコミットSHA（配布時に実際の値を記入）
- 案件固有の適用節（例：SA-management の「工程完了とmainへの反映（AIメモSA管理での適用）」）は、写しの中に「案件固有適用」と明記した節として残してよい。共通節と同題で内容の違う節を並存させない。固有節が共通節を上書きする場合はその旨を固有節の冒頭に書く。
- 改訂の手順（README に記載する内容）：①standards へ改訂をコミット（正本の改訂）→②設計・管理側が配布指示を1本出す→③Claude Code が各対象リポジトリの写しを更新し、冒頭2行のSHAを更新、全対象でファイル内容一致を確認して報告→④設計・管理側が照合検査。
- 配布対象：共通規約2文書を保有するリポジトリ（現時点：Weekly-Tasks・Aegis-Mesh・New-Sales-Cases・Billing-Reconciliation-System・SA-management の5件）。未保有のリポジトリ（external-voice-poc・AI-memo 等）への新規配布は本書の対象外とし、必要になった案件で個別にユーザーへ諮る。

## 3. 実施内容（Claude Code。順に実施し、各段で報告）
1. リポジトリ standards（非公開）の新設。作成権限が無い場合は停止し、ユーザーが GitHub の Web 画面で空リポジトリを作る手順（場所・押すもの）を示す。
2. Weekly-Tasks 現行の2文書を standards へ初版としてコミット（内容は一字も変えない）。README.md に §2 の改訂手順を記載。
3. 5リポジトリの写しの冒頭へ2行（正本の場所・写しの元SHA）を追加。本文は変更しない。SA-management の固有節に「案件固有適用」の明記を追加（節の内容は変えない）。
4. 全対象で standards 版と写しの本文一致（冒頭2行を除く）を機械照合し、結果を報告。
5. 記録：standards 側 README と、Weekly-Tasks の tasks/CHAT_CURRENT.md に本改修の実施を記録。

## 4. セットで要る対のもの（対の明記）
- ブランチと工程完了：各案件リポジトリと standards は main。Weekly-Tasks は claude/gallant-dijkstra-m5gen1 で作業し、工程完了は規約「工程完了とmainへの反映」どおり main へのマージ・反映確認まで含める（main の現状は実装前の静的確認で報告し、反映手順を工程に含めて示す）。書き込み前に最新SHA確認。
- 工程完了は規約「工程完了とmainへの反映」どおり、main への反映・反映確認まで含める。
- 記録：CHAT_CURRENT.md と TASK_CURRENT.md 冒頭欄（Weekly-Tasks 側）の両方を更新。

## 5. 受入条件
- standards を見れば2文書の正本と改訂履歴が分かる。
- 各写しの冒頭2行だけで「正本の場所」と「写しが正本のどの版か」が分かり、機械照合で最新かを検査できる。
- 今回の初回配布で、5リポジトリの写しが standards 初版と一致している。

## 6. 作業制限・禁止事項
- 2文書の本文内容の改訂は本書では行わない（運用の整備のみ）。
- 公開設定の変更は standards の新設以外に行わない。各案件の公開設定を変えない。
- 自動同期・定期同期の仕組みを作らない（規約§7維持）。
- 秘密情報をコミットしない。

- 判定：完了／停止／要確認
- 作成・変更したリポジトリ／ファイル／コミットID（standards と5リポジトリ分）
- 一致照合の方法と結果
- 記録（CHAT_CURRENT・TASK_CURRENT 冒頭欄）：済／未
