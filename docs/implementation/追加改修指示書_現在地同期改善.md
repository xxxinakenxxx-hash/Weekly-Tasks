## 1. 目的（ユーザー要求 2026-10-23）
- 現在地の「とれの悪さ」を解消する：不一致・要確認で現在地が空のまま放置される、案件キーが入らず結びつかない、実装前の案件が止まって見える、キー確認不能が量産される——の4点。
- ユーザー方針：帳面は日付（日時）が新しい記録を正とするのが普通。これを巡回の軸にする。

## 2. 確定項目（2026-10-23 ユーザーが1項目ずつ承認）

### 項目1　日時が新しい方を正とする
- 巡回（週次・日次）の判定基準C を変更する。情報源（TASK_CURRENT.md、CHAT_CURRENT.md 冒頭定型欄、Drive 資料、コミット日時、シート前回記録）が食い違う場合、各記載の日時（日付＋時刻。コミットは秒まで、台帳・定型欄は記載の日付＋取得できる更新時刻）を比べ、最も新しい記載を現在地として採り、取得結果は「確認済み」とする。古い方との食い違いは注記（日次は「内容」、週次は「要確認」欄）に「食い違い検出：（何と何がどう違うか）」として残す。
- 日時がどの情報源からも取れない、または最も新しいものが同時刻で中身が違う場合だけ、従来どおり「不一致／要確認」とし現在地を空にする。
- 「前回より前の工程へ戻る」場合の判定基準B の安全装置（明記された巻き戻しだけ採る）は変えない。

### 項目2　リポジトリ指定でのキー入力（週間タスク画面）
- 週間タスク画面「詳細・編集」の案件キー欄を改善する。リポジトリのアドレス（例 https://github.com/xxxinakenxxx-hash/Aegis-Mesh、末尾の .git や /tree/… は許容）またはローカルフォルダの場所（例 C:\Users\inamori240\Documents\Aegis-Mesh）を貼ると、画面が所定のキー形（GitHub は https://github.com/xxxinakenxxx-hash/（リポジトリ名）/blob/HEAD/tasks/TASK_CURRENT.md、ローカルは （フォルダ）\tasks\TASK_CURRENT.md）に整えて入れる。所定の形に整えられない値はその場で理由を表示し、入れない。
- 欄の説明書きを更新する：「案件キー（リポジトリの場所。日次AI現在地の自動同期と、翌週以降の指示ルート引継ぎに使う。リポジトリのアドレスを貼れば形を整えます。空欄なら同期・引継ぎをしない）」。
- 既に正しい形の値が入っている欄の値は変えない。朝ブリーフ画面には入力欄を追加しない（閲覧のみのまま。実装前の静的確認で表示上の注記の要否だけ提案してよい）。

### 項目3　実装前の案件は CHAT_CURRENT 冒頭定型欄を読む
- 巡回（週次・日次）の判定基準A を拡張する。TASK_CURRENT.md の冒頭の欄が実装前（未着手・指示未発行・企画検討・正本整備等）を示す案件では、同リポジトリの tasks/CHAT_CURRENT.md 冒頭定型欄（段階・現在地・最終更新の3行）を現在地の根拠に加え、項目1の日時比較で新しい方を採る。
- 定型欄が無い・読めない場合は従来どおり TASK_CURRENT.md だけで判定し、注記に「要確認（CHAT_CURRENT 定型欄なし／未更新）」と書く（規約3-1 の読み分け規則と同文）。

### 項目4　日次巡回は AI案件.md を読んでよい
- 日次巡回（予約「日次AI現在地巡回」の前段）の禁止「『週間タスク』フォルダ（Obsidian Vault）には保存しない・読まないでください」を、「保存しない。読むのは AI案件.md のみ可」に変更する。用途：既存案件キーの照合（1-5 の『前回の結果』2系統を両方読める状態に戻す）と、週次時点の現在地・情報源整合との突き合わせ。
- 朝ブリーフ後段の材料（予定・タスク・AI案件現在地の値）は従来どおり朝情報.md・AI案件_日次現在地.md・Sheets から取り、AI案件.md の内容を朝ブリーフの本文に直接使わない。通常業務.md は引き続き読まない。
