週間タスク・朝ブリーフ　追加改修指示書 v1.0（2026-10-09 ユーザー指示）

> 位置づけ：IS-00〜IS-06、追加実装指示書 v1.2 とは別の独立した追加改修とする。IS-06 総合試験・受入は継続中のまま（完了扱いにしない）。既存データ・受入作業を壊さない。

## 0. 正本との関係（仕様変更記録）

- 正本 v1.7（統合企画書・案件概要書・機能仕様書 F-08／F-10、データ設計書 §3）は状態を「未着手／進行中／完了／次週候補／持越し」の5値と定めている。本改修で「保留」を加え6値とする。
- 正本4点は書き換えない。正本との差分は本書で管理する。
- 状態を1項目で管理し、複数フラグに分けない原則は維持する。

## 1. 目的

状態に「保留」を追加する。保留の定義：今週は何もせず、来週以降に実施するタスク。

## 2. 状態6種類

| 状態 | 定義 |
|---|---|
| 未着手 | 今週実施予定だが、まだ着手していない |
| 進行中 | 作業を進めている |
| 完了 | 作業が終了した |
| 保留 | 今週は何もせず、来週以降に実施する |
| 次週候補 | 次週に実施する候補 |
| 持越し | 今週完了できず、翌週も継続する |

「保留」は独立した状態として管理し、「次週候補」「持越し」と混同しない。

## 3. 改修要件

### A. 週間タスク画面
- 状態選択肢に「保留」を追加する。既存の5状態は維持する。
- 状態変更はGoogle Sheetsへ保存し、変更履歴を記録する。再読込後も「保留」が保持される。

### B. 朝ブリーフ画面
- タスクの状態選択肢に「保留」を追加し、保留状態を正しく表示する。
- 朝ブリーフでの状態変更を週間タスク画面と同期する。
- 保留タスクを「今日優先すること」へ、状態だけを理由として追加しない（ChatGPT Project の朝ブリーフ指示文に規則を追加）。

### C. Google Sheets
- 「タスク」シートの状態列を6種類に対応させ、入力規則を更新する（選択肢だけを更新）。
- 列の追加は行わない。既存タスクの状態を勝手に変更しない。状態変更履歴を保持する。

### D. 翌週への引継ぎ
- 「保留」は翌週の自動持越し対象に含めない。
- 翌週になっても自動的に「未着手」「次週候補」「持越し」へ変更しない。
- 元の週の保留状態と履歴を維持する。
- 将来実施する際は、ユーザーが改めて対象週のタスクとして扱う。
- 既存の「次週候補」「持越し」の処理は変更しない。

### E. 仕様・管理資料
- 確定事項を docs/DB_SCHEMA.md と本書へ反映する。正本4点は上書きしない。

## 4. テスト

- 週間タスク画面での保留設定
- 朝ブリーフ画面での保留設定
