# 追加改修指示書 — 案件キーの初期登録・指示ルート継続（④）とAI案件現在地の区別（③）

週間タスク・朝ブリーフ　追加改修指示書 v1.0（2026-10-09 ユーザー指示、GitHub Issue #1）

> 位置づけ：IS-00〜IS-06、追加実装指示書 v1.2、追加改修「保留」「指示ルート」とは別の独立した追加改修。IS-06 総合試験・受入は継続中のまま。公開版1は変更しない。

## 1. 解決すべきこと（ユーザー指示）
1. 既存AI案件の案件キーを、AI案件.md の情報から安全に初期登録する。ユーザーに手入力させない。
2. 毎週の週間分析で、指示ルートを再設定せずに引き継げるようにする。
3. 日次巡回で取得した現在地が週間タスク・朝ブリーフに反映されない原因を特定し、修正する。
4. 未確認情報と最新の確認済み情報を区別し、古い現在地を最新と誤認させない。
5. 週間・日次の案件識別方法を整合させる。

## 2. 調査結果（2026-10-09、実データ）
- Sheets「朝ブリーフ」：保存は 2026-10-02 と 2026-10-06 の2行だけ。10/7〜10/9 の保存なし。
- Sheets「履歴」：「修正／AI案件現在地」は0件。日次AI現在地の同期は一度も実行されていない。
- Sheets「タスク」：10/5週のAI案件4行（16〜19行目）の「AI案件現在地」は、10/5 の週間分析JSONの値（AI案件.md 確認日 10-05 の要約）のまま。案件キーは4行とも空欄。
- AI案件.md（確認日 2026-10-05）：4案件とも情報源整合が「不一致」または「要確認」（Codexチャット未確認を含む）。
- 朝情報.md：10/9 06:28 に自動更新されている。
- AI案件_日次現在地.md：作業環境のDrive検索では見つからず、内容は未確認（会社アカウントのファイルのため）。

### 原因
1. 同期は朝ブリーフの「保存」時だけに動く。10/7 以降、朝ブリーフJSONが保存されていないため、日次巡回の結果は Sheets に届いていない（データで確認）。
2. 仕様上、取得結果が「確認済み」のときしか現在地を更新しない。巡回結果は Codexチャット未確認・不一致になりやすく、保存しても現在地が変わらない（10/5 の週次は4件とも確認済みではない）。
3. 画面の現在地には根拠（日次で確認済みか、週間分析の値か）と時点が表示されず、週間分析時点の値が最新に見える。
4. 週次（案件キー）と日次（ChatGPTが案件名から taskId を対応付け）で識別方法が違い、名称の揺れで同期できない／誤る余地がある。
5. 既存行に案件キーが無いため、指示ルートの継続（案件キー一致）が初回に働かない。

## 3. 対応
### 3.1 案件キーの初期登録（1回だけ・承認後に実行）
- 対象：2026-10-05 週のAI案件4行。出典は AI案件.md（確認日 2026-10-05）の各案件の「TASK_CURRENT.md：（場所）」。
- 対応の根拠：10/5 週のAI案件行は、この AI案件.md から作った週間分析JSONで作成された。見出し（## N. 案件名）とタスク名が完全一致し、4件が1対1。
- 実行方法：/dev の URL に `?view=casekey` を付けた確認ページで、変更前（空欄）・変更後（場所）を表示し、「実行」を押したときだけ書き込む。書き込み前に、行の実在・対象週・AI案件・未削除・タスク名一致・案件キー空欄・同じキーの重複なしを1件ずつ確認し、1件でも満たさなければ何も書かない。履歴は「修正／案件キー」。再実行しても書き換えない。
- 9/28 週の行（タスク名が「営業AI音声メモ」「機械販売事例まとめアプリ」など AI案件.md の見出しと一致しない）は対象にしない。

### 3.2 指示ルートの継続
- 初期登録後、翌週の週間分析JSON（案件キーつき）で作るAI案件は、前の週の同じ案件キーの行から指示元・実装先を引き継ぐ（追加改修④の継続処理）。ユーザーの再設定は不要。

### 3.3 週次・日次の識別の統一
- 朝ブリーフJSONの「AI案件現在地」に「案件キー」（AI案件_日次現在地.md の確認元 TASK_CURRENT.md の場所）を加え、今週の「タスク」の案件キーで突き合わせる。taskId が案件キーと別の行を指す場合は同期しない。案件キーが無い項目は従来どおり taskId。
- 手動追加のAI案件は、案件キーが設定されていれば案件キーで同期する（安全な対応のため）。無ければ従来どおり対象外。

### 3.4 現在地の区別
- 「タスク」に19〜22列を追加：現在地確認日時／最新取得日時／最新取得結果／最新取得現在地。
- 朝ブリーフ保存時、当日取得の結果はすべて「最新取得」に記録する。「確認済み」のときだけ「AI案件現在地」と「現在地確認日時」を更新する。
- 画面：現在地に「確認済み MM/DD HH:mm」または「日次で未確認」を添える。確認済みより新しい未確認の取得は「最新取得 MM/DD HH:mm：（現在地）［区分］」として別の行に表示する。同期結果は確認済み／未確認として記録／更新しない（理由）に分けて表示する。
- 古い日付の取得は記録しない（当日取得として扱わない）。

### 3.5 指示文
- docs/prompts/project_morning_brief.md：「案件キー」を日次ファイルから写し、taskId はタスクシートの案件キーが同じ行から取る。案件名で対応付けない。

## 4. 実データでの検証方法
- 初期登録：確認ページで4行の変更前後を確認→実行→Sheets「タスク」R16〜R19 と履歴「修正／案件キー」4行を照合。
- 日次：日次巡回（平日 6:15）→朝ブリーフJSON（案件キーつき）→保存→同期結果の表示と、「タスク」19〜22列・「AI案件現在地」・履歴を照合。
- 週次：10/12 の週間分析JSON（案件キーつき）→確定→営業AIメモの指示ルートが引き継がれていることを確認。

## 5. 作業制限
- 実Sheetsの既存データ（案件キーの初期登録）は、変更対象と内容を報告し、ユーザーの承認（確認ページでの実行）後にだけ書き込む。
- 公開版1は変更しない。①保留・④指示ルート・操作マニュアルリンクは変えない。
