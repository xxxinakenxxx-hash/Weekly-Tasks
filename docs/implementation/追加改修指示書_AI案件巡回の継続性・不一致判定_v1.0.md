# 追加改修指示書 — AI案件巡回の継続性・不一致判定の是正

週間タスク・朝ブリーフ　追加改修指示書 v1.0（2026-10-11 ユーザー指示・決定）

> 位置づけ：IS-06 受入前の追加改修。IS-06 は継続中のまま。公開版1は変更しない。各案件の TASK_CURRENT.md の過去記録、AI案件.md の内容、Sheets の正データは変更しない。

## 1. 問題（調査結果、2026-10-11）
- 週次と日次で、同じ案件の現在地・不一致の判定が食い違う。例：管理職AIメモは 10/5 週次「IS-13」、10/12 週次「IS-02完了／IS-03待ち」、10/12 日次「冒頭の最新記録はIS-13の停止、台帳の『現在地』節に古いIS-02の記述が残る」。機械売上管理システムも 10/12 週次「IS-16」、日次「PH1-FIX-03B」。
- 根本原因
  1. 作業台帳（TASK_CURRENT.md）に、新しい記録と更新されていない古い「現在地」節が併存し、巡回指示文に「どこを現在地とするか」の決まりが無い（週次は古い節、日次は冒頭の最新記録を採った）。
  2. 週次巡回は日次の結果・Sheets の前回値を読まない。月曜は週次（5:45）が日次（6:15）より先で、朝ブリーフ（10/12 08:20 保存）の時点で今週の「タスク」行が無く、日次結果は記録されなかった。
  3. 判定の決まりが「一致しなければ不一致」だけで、資料の時点を比べない。Codexチャットを特定できないと「確認済み」にならず、現在地が実質更新されない。
  4. 案件キー・持越し元・申し送り・履歴・最新取得の欄があるのに、巡回・週間分析の手順で使われていない。

## 2. ユーザー決定（2026-10-11）
1. 作業台帳の中で、日付のある記録のうちいちばん新しいものを今の現在地とする。
2. 古い資料との違いは不一致にしない（最新でよい）。
3. 台帳の最新の記録とDriveが一致していれば、Codexチャットを特定できなくても「確認済み」とし、内容欄に「チャット未確認」と書く。
4. 週次で前回とのつながりを確かめる方法は Claude Code に任せる。
5. 月曜の日次の結果が失われないようにする。

## 3. 対応
### 3.1 巡回指示文（週次・日次共通の「現在地の決め方と判定」）
- 決定1〜3を、docs/prompts/desktop_work_ai.md・desktop_work_ai_daily.md に書く。台帳内の古い記載・古い資料は不一致の理由にせず注記するだけ。不一致は、最新の記録と同じ時点かそれより新しい資料が別の内容を示す場合だけ。
- 書式（docs/OBSIDIAN_FORMAT.md・docs/AI_DAILY_FORMAT.md）に「台帳の最新記録日」を追加。

### 3.2 前回とのつながり（決定4の設計）
- 週次巡回：直近の AI案件_日次現在地.md の同じ案件の「台帳の最新記録日」と比べ、今回のほうが古ければ読み直し、それでも古ければ要確認に注記。
- 週間分析（docs/prompts/project_weekly_analysis.md）：AI案件.md の「台帳の最新記録日」を、「タスク」の前の週の同じ案件キーの行の「現在地確認日時」「最新取得日時」と比べる。古ければ AI案件.md の現在地を採らず、AI案件現在地を空欄にして（保存時に前の週の値を引き継ぐ）例外情報に「要確認：週次巡回の記録が前回の記録より古い」と書く。チャット未確認・古い資料の注記だけの案件は例外情報にしない。

### 3.3 月曜の日次結果（決定5、アプリの変更）
- 朝ブリーフ保存時、案件キーが一致する今週の行が無ければ、いちばん新しい前の週の同じ案件キーの行（その週に1行だけ）に記録する。今週の同じ案件キーの行を削除した場合と、前の週に同じ案件キーの行が複数ある場合は記録しない。taskId だけの項目は従来どおり今週のみ。
- 週間分析の確定で案件キーつきのAI案件を新しく作るとき（持越しを除く）、前の週の同じ案件キーの行から最新取得を写す。前の週の「現在地確認日時」が対象週の月曜以降（月曜朝の日次で確認済み）なら、その現在地と確認日時を週間分析の値より優先して採る。AI案件現在地が空欄なら前の週の値と確認日時を写し、同じ値なら確認日時を写す。
- 対象：src/Brief.js（planAiSync_）、src/Board.js（latestCaseRow_・caseAiState_・commitWeekBoard）。テスト：tests/ai_state.test.js。

## 4. 不一致の解消条件
- 同じ案件キーで、台帳の最新の記録と、同じ時点かそれより新しい資料（Drive・開発履歴・チャット）が一致し、次の巡回で「一致／確認済み」になったとき。
- 本当の食い違い（例：機械販売事例アプリの取材方式）は、ユーザーが方式を決め、その案件の台帳または正本に記録されるまで「不一致」のまま残す。解消済み扱いにしない。

## 5. 継続性の確認方法
- 自動テスト：月曜の前の週の行への記録、週間分析の確定での引継ぎ（確認済みの優先、未確認の扱い、先週の確認済みは優先しない）、削除・複数行・taskIdのみの除外。
- 実データ：次の月曜に、週次巡回 → 日次巡回 → 朝ブリーフ保存 → 週間分析の確定 の順と、週間分析の確定 → 朝ブリーフ保存 の順のどちらでも、Sheets「タスク」19〜22列・AI案件現在地・履歴が前の週から続いていること。管理職AIメモで IS-02 が現在地として採られないこと。機械販売事例アプリが不一致のまま残ること。
