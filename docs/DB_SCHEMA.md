## 設計上の決め事
- 状態とは別に完了／未完了・持越し等のフラグ列を作らない（IS-00 禁止事項）。
- 変更は必ず履歴シートへ記録する（開発工程表 §5「状態変更・編集は履歴を残す」）。
- 例外情報・AI案件現在地は文字列1列で保持する。詳細な項目分解はデータ設計書 §6 で未確定のため、後続工程で必要になった時点で列を追加する（既存列は変えない）。
- 持越し元との関連付け（IS-04）：前週で状態が「次週候補」「持越し」のタスクを翌週へ取り込むとき、翌週に新しい行を作り「持越し元タスクID」に元のIDを入れる。前週の行・履歴は変更しない。同じ元からの二重取り込み、対象週に同名がある取り込みは拒否する。
- 既存の13列の「タスク」シートは、読み書き時に「持越し元タスクID」列（14列目）の見出しだけを末尾に追加する（既存の列・行は変更しない）。
- 削除（IS-06、2026-10-06 ユーザー決定 A案）：「タスク」の行は物理削除しない。「削除済み」列に TRUE を入れ、履歴に「削除／項目＝削除済み／変更前＝空欄／変更後＝TRUE」を1行記録する。削除済みのタスクは、週間ボード・朝ブリーフの今週タスク・持越し候補・同名の重複判定の対象外。削除済みの行は変更できない。持越しの二重取り込み防止は削除済みの行も含めて判定する（削除した持越し行の元が再び候補に出ない）。既存の14列の「タスク」シートは、読み書き時に「削除済み」列（15列目）の見出しだけを末尾に追加する。「履歴」の「操作」列の入力規則に「削除」が無ければ選択肢だけを更新する。
- 複数曜日（追加実装 v1.1）：1タスク＝1行・1タスクIDのまま、「曜日」に複数の曜日を持つ（曜日ごとに行を複製しない）。保存形式は月→金の固定順を「,」でつないだ文字列で、重複なし。既存の単一曜日の値はそのまま有効。入力規則は月〜金の空でない組み合わせ31通り（既存の入力規則が単一曜日だけの場合は、読み書き時ではなく setupSheets／複数曜日の保存時に選択肢だけを更新し、値は変えない）。曜日の変更は「確定して保存」でまとめて保存し、履歴に変更前後を残す。
- AI案件現在地の日次同期（追加実装 v1.1）：朝ブリーフ保存時、JSONの「AI案件現在地」のうち取得結果が「確認済み」、taskId が朝ブリーフの日付の週の「タスク」行（削除済みを除く、種別AI案件）と一致し、取得日時が当日のものだけを、その行の「AI案件現在地」へ同期し、履歴（修正／AI案件現在地）を残す。要確認・不一致・取得失敗・チャット未確認は上書きしない。前回と同じ現在地は書き換えない。最新の確認済み現在地＝「タスク」、過去の変更＝「履歴」、今回の日次巡回結果＝朝ブリーフJSON とし、「朝ブリーフ」シートにAI現在地の列は持たない。
- 手動タスク追加（追加実装 v1.2）：週間タスク画面の「＋ タスク追加」から、表示中の週へ確定タスクとして1行追加する（候補にしない）。新しいタスクIDを採番し、複数曜日でも1行。状態は「未着手」。受け付ける項目はタスク名・種別・曜日・優先度・重点・メモ・AI案件現在地（種別AI案件のときだけ）。履歴は既存の操作区分を使い「作成」・項目「手動追加」で1行記録する（「操作」列の入力規則に値を加えない）。列・状態値・入力規則は変更しない。対象週に同名のタスクがある場合は追加しない。手動追加のAI案件（持越し後の行を含む）は、AI案件現在地の日次同期の対象外。
- 状態「保留」（追加改修 2026-10-09。docs/implementation/追加改修指示書_状態「保留」追加_v1.0.md）：保留＝今週は何もせず、来週以降に実施するタスク。状態は6値（未着手／進行中／完了／保留／次週候補／持越し）。列は追加しない。「状態」列の入力規則に「保留」が無い場合は、setupSheets／初めて保留を保存するときに選択肢だけを6値へ更新し、既存の値は変えない。保留は翌週の自動持越し（「前週の次週候補・持越しを取り込む」）の対象外で、翌週になっても自動で状態を変えない（元の週の行・履歴はそのまま）。来週以降に実施するときは、ユーザーが改めて対象週のタスクとして扱う。状態の変更は「状態変更」として履歴に残す。
- 指示ルート（追加改修④ 2026-10-09。docs/implementation/追加改修指示書_指示ルート追加_v1.0.md）：AI案件ごとに「指示元」「実装先」を持ち、週間タスクのカードに「指示ルート：指示元 → 実装先」と常時表示する（空欄は「未設定」と表示し、推測で補わない）。通常タスクには表示せず、設定もできない。入力は画面のドロップダウン（ChatGPT／Claude／Claude Code／Codex／Gemini／その他／未設定）で、「その他」を選んだときだけ自由入力。「未設定」は空欄として保存する。保存値は文字列のまま（「その他」の自由入力があるため、Sheetsの列には入力規則を付けない）。選択肢にない保存済みの値は、画面で「その他」＋その値として表示する。「詳細・編集」で変更し「確定して保存」で保存、履歴は「修正／指示元」「修正／実装先」。前週の次週候補・持越しを取り込むときは、指示元・実装先も新しい行へ引き継ぐ。既存の15列の「タスク」シートは、読み書き時に「指示元」「実装先」「案件キー」（16〜18列目）の見出しだけを末尾に追加する（既存の値・行は変えない）。 継続処理：指示ルートはAI案件単位で引き継ぐ。AI案件の識別は「案件キー」（AI案件.md に記載された TASK_CURRENT.md の場所。比較は前後の空白・「/」「\」・大文字小文字の違いを同じとみなす）で行い、タスク名では行わない。週間分析JSON等で新しく作るAI案件に案件キーがあり、指示元・実装先とも空欄なら、対象週より前の週で同じ案件キーのいちばん新しい週の行（削除済みを除く）の指示元・実装先を入れる（空欄に戻されていれば空欄）。その週に同じ案件キーで指示ルートが食い違う行がある場合、案件キーが無い場合、前の週に無い場合は引き継がず「未設定」。指示ルートが更新されるのはユーザーが明示的に変更したときだけで、前後の週の行は自動で変えない。対象週の中で同じ案件キーのAI案件は1件だけ。
- 日次記録粒度はデータ設計書 §6 で未確定。日々の更新は「履歴」シートの日時つき記録で追える。
- 例外・不一致の保持（IS-05）：列は追加しない。「例外情報」列に「区分：内容」を保持し、複数ある場合は「／」でつなぐ（区分の直前の「／」だけを区切りとみなす）。内容に根拠を書く。
  - 区分「不一致」「チャット未確認」を含む候補（持越し候補を含む）は、週間画面でカードごとに確認チェックを入れたものだけ保存する。サーバーも確認のない採用を拒否する（自動確定しない）。確認チェック自体は保存しない。
  - 例外情報は週間画面で修正・解消（空欄）できる。変更は「履歴」シートに日時・変更前・変更後で残り、根拠・状態・時点を追跡できる。週間画面の各カードで変更履歴を表示する。
  - 画面の読込に失敗したときは、別の週・別の日の内容を表示しない。同じ週・日の前回値を残すときは「前回値」と読込時点を明示する。正データの読込時点を画面に表示する。
