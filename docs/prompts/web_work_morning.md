# Web版Work 毎朝の指示文（当日情報 → 朝情報.md）

毎朝、Web版Workへ次をそのまま送る。Gmail・Googleカレンダー・Google Driveは会社アカウントで接続する。
日次経路ではObsidian（「週間タスク」フォルダ）を使わない。
追加実装 v1.1：朝ブリーフJSONを作る時刻までに完了させる（自動実行の設定状態と実行時刻は docs/WORK_SCHEDULE.md に実機で確認した内容を記録する）。AI案件の現在地は、デスクトップ版Workの日次巡回（desktop_work_ai_daily.md）が別に集める。

```
今日の朝ブリーフ用の当日情報を収集し、Google Drive「週間タスクボード」フォルダ直下の「朝情報.md」へ保存してください。
「週間タスク」フォルダ（Obsidian Vault）には保存しない・読まないでください。

対象：今日の Googleカレンダーの予定、Gmail の要対応メール（昨日以降に届いたもの）、今日に関係する Google Drive 上の資料。
次の書式で書いてください。

# 朝情報

日付：（今日 yyyy-MM-dd）
取得日時：（yyyy-MM-dd HH:mm）

## 今日の予定
- HH:mm〜HH:mm 件名（場所）

## 要対応メール
- 件名／送信者／要点／期限（不明は「要確認」）

## 関係する資料
- ファイル名／要点

## 取得できなかった情報
- （取得に失敗した情報源があれば「取得失敗：情報源名」。なければ「なし」）

保存ルール：
- 保存前に、Google Drive「週間タスクボード」フォルダ直下だけを対象に、ファイル名が完全一致する「朝情報.md」を検索する。
- 「朝情報.md」が1件だけ存在する場合は、その既存ファイルのファイルIDを特定し、その同じファイルIDの内容を今回の朝情報で更新する。別の同名ファイルを新規作成してはいけない。
- 「朝情報.md」が0件の場合だけ、新規作成してよい。
- 「朝情報.md」が2件以上ある場合は、どれかを推測で選ばず保存を中止し、「保存失敗：同名ファイル複数」と報告する。
- 既存ファイルの更新に失敗した場合は、削除・新規作成・別名保存・同名ファイル新規作成で代替せず、「保存失敗」として停止する。
- 保存後に対象ファイルを再取得し、ファイル名、保存先、内容の日付、ファイルIDを確認する。
- 既存ファイルを更新した場合は、保存前後でファイルIDが同一であることを確認する。同一でなければ完了扱いにしない。

ルール：
- 推測で埋めない。判断できない点は「要確認」と書く。
- 保存後、ファイル名・保存先・ファイルID・予定件数・要対応メール件数・保存結果（新規作成／既存ID更新／保存失敗）を報告する。
```
