# ChatGPT Project 朝ブリーフ 指示文（→ 朝ブリーフ画面へ貼り付けるJSON）

Web版Workの `朝情報.md` と、Desktop版Workの `AI案件_日次現在地.md`（日次AI現在地巡回）の保存後、ChatGPT Project の新しいチャットへ次を送る。Google Driveは会社アカウントで接続する。
出力形式は docs/BRIEF_FORMAT.md。日次経路ではObsidianを使わない。朝ブリーフJSONは1本だけ作る（追加実装 v1.1）。

```
今日の朝ブリーフを作ってください。次を実際に開いて読み、推測で答えないでください。
- Google Drive「週間タスクボード」フォルダ直下の「朝情報.md」
- Google Drive「週間タスクボード」フォルダ直下の「AI案件_日次現在地.md」
- スプレッドシート「週間タスクボード」の「タスク」シートのうち、今週（対象週＝今週の月曜）で「削除済み」が空欄の行（タスクID・タスク名・種別・曜日・状態・優先度・重点・実施結果・メモ・次回申し送り・例外情報・AI案件現在地・案件キー）
「週間タスク」フォルダ（Obsidian Vault）の「通常業務.md」「AI案件.md」は読まないでください。

結果は次のJSON形式「だけ」で出力してください。説明文やコードブロック記号（```）は付けないでください。

{
  "日付": "（今日 yyyy-MM-dd）",
  "今日の一言": "今日はどんな一日か（短い見立て）",
  "今日の流れ": ["HH:mm 予定", "..."],
  "今日優先すること": ["今日の曜日に配置されたタスク・要対応メールのうち優先するもの", "..."],
  "気にかけておきたいこと": ["期限接近・要確認・不一致など", "..."],
  "もう片づいていること": ["今週のタスクで状態が完了のもの", "..."],
  "未完了・持越し": ["今週のタスクで未着手・進行中のまま気にすべきもの、状態が持越し・次週候補のもの", "..."],
  "AI案件現在地": [
    {"案件キー": "（AI案件_日次現在地.md のその案件の TASK_CURRENT.md の場所）", "taskId": "（タスクシートで案件キーが同じ行のタスクID）", "案件名": "...", "取得結果": "確認済み", "現在地": "確認できた現在地", "取得日時": "yyyy-MM-dd HH:mm", "内容": ""}
  ]
}

ルール：
- 項目が無い場合は空配列 [] にする。
- 「今日の流れ」は朝情報.md の今日の予定を時刻順に並べる。
- タスクの状態は「タスク」シートの値をそのまま使い、推測で変えない。
- 状態が「保留」のタスク（今週は何もせず、来週以降に実施する）は、状態だけを理由に「今日優先すること」に入れない。
- 例外情報（要確認・不一致・チャット未確認・取得失敗）があるタスクは「気にかけておきたいこと」に区分ごと書く。
- 朝情報.md に「取得失敗」がある場合、または朝情報.md・タスクシートを読めなかった場合は、「気にかけておきたいこと」に「取得失敗：内容」と書く。
- 「今日の曜日に配置されたタスク」は、タスクシートの「曜日」（「月,火,水」のように複数のことがある）に今日の曜日を含むタスク。
- 「AI案件現在地」は、AI案件_日次現在地.md に載っている案件ごとに1件書く。
  - 「案件キー」は、AI案件_日次現在地.md のその案件の「確認元 - TASK_CURRENT.md：（ファイルの場所）」を一字も変えずに書く（追加改修④③：週次・日次で同じ識別）。場所が書かれていない場合は空にする。
  - 「taskId」は、タスクシートの「案件キー」列がその場所と同じ行のタスクIDを書く。同じ行が無い場合は空にする。案件名（タスク名）で対応付けない（推測しない）。
  - 取得結果・現在地・取得日時・内容は、AI案件_日次現在地.md の該当案件の記載をそのまま使う。現在地を推測で補わない。
  - 取得結果は 確認済み／要確認／不一致／取得失敗／チャット未確認 のいずれか。確認済みのときだけ現在地を書く。
  - AI案件_日次現在地.md を読めない場合、または取得日が今日でない場合は、全件を「取得失敗」とし、内容に理由を書く（前回の値を今日の現在地として書かない）。
  - 確認済み以外の案件は「気にかけておきたいこと」にも「区分：案件名／内容」で書く。
```
