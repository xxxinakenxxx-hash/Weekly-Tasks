週間タスク・朝ブリーフ ユーザー操作マニュアル

この手順で、週のタスクを登録し、平日の朝ブリーフを保存します。ChatGPT に貼る文は、このページの付録A〜Cの「コピー」ボタンでコピーしてください（付録の文は、いつも最新のものです）。

週間タスク画面：

実施するタイミング

いつあなたがすること
毎週月曜 5:45Desktop版WorkのAI案件の週次巡回は自動です。何もしません。
毎週月曜、業務開始後「毎週月曜に行う操作」の1〜4を行います。
平日 6:15・6:30 の自動処理後Desktop版Work（AI案件の日次巡回）とWeb版Work（朝情報）は自動です。そのあと「毎朝に行う操作」の1〜3を行います。

画面表示や通知で自動処理が失敗したと分かった場合は、JSONの作成・保存へ進まず、そのままの状態で連絡してください。

毎週月曜に行う操作

1. Web版Workで通常業務を集める

ブラウザで https://chatgpt.com/ を開き、Web版Workを選んで新しいチャットを開きます。付録Aをコピーして貼り付け、送信します。

2. 週間タスクのJSONを作る

ChatGPT のプロジェクト「週間タスク」で新しいチャットを作ります。付録Bをコピーして貼り付け、送信します。返ってきた JSON（{ から } まで）を全部コピーします。

3. 週間タスク画面へ読み込む

週間タスク画面を開き、「ChatGPT Project の分析結果を読み込む」を開きます。JSONを貼り付けて「読み込む」を押します。

4. 内容を確認して保存する

  • 新しいタスクは「候補」として出ます。
  • 今週の表にすでにあるAI案件は「分析結果で更新」と出ます。保存すると、現在地と例外情報が新しい内容に変わります（内容が同じなら「内容に変わりなし」）。
  • 不一致・チャット未確認のカードは、内容を確かめてカードの確認欄にチェックを入れます。
  • 「確定して保存」を押します。今週の要点・コーションも一緒に保存され、再読込しても消えません。

AI案件の巡回をやり直したときも、2〜4をやり直せば今週の表が新しい内容に直ります。

毎朝に行う操作（月〜金）

1. 朝ブリーフのJSONを作る

プロジェクト「週間タスク」で新しいチャットを作ります。付録Cをコピーして貼り付け、送信します。返ってきた JSON を全部コピーします。

2. 朝ブリーフ画面へ読み込む

画面上部の「朝ブリーフ」タブを押し、「ChatGPT Project の朝ブリーフを読み込む」を開きます。JSONを貼り付けて「読み込む」を押します。

3. 内容を確認して保存する

日付、今日の予定、今日やること、重要な注意、AI案件現在地を確かめて「保存」を押します。保存すると、確認できたAI案件の現在地が今週の表にも入ります（週間タスク画面のカードに「確認済み 日時」と出ます）。

日中にタスクの結果を記録する

朝ブリーフ画面の「今週のタスク」で記録するタスク名を押し、「状態」「曜日」「実施結果」「メモ」「次回申し送り」を入れて「この内容で保存」を押します。週間タスク画面では「✎ 記録」から入力し、「確定して保存」を押します。

AIが拾わなかったタスクを追加する

週間タスク画面で「＋ タスク追加」を押します。タスク名・種別・曜日・優先度・重点・メモを入れて「追加して保存」を押します。

止める条件

  • Workが保存できなかった、またはJSONの作成で資料の取得失敗が出た。
  • 週間タスクJSONの対象週が今週と違う。
  • JSONを「読み込む」で受け付けない、または画面にエラーが出る。
  • 保存後に「保存しました」と出ない。

この場合は保存を繰り返さず、エラーの表示を残して連絡してください。

付録A　通常業務を集める指示文 コピーしました

毎週月曜、Web版Workの新しいチャットへ送ります。

今週分の通常業務情報を収集し、Google Drive「週間タスクボード」フォルダ内「週間タスク」フォルダ直下の「通常業務.md」へ保存してください（既存ファイルがあれば上書き。サブフォルダは作らない）。

対象：今週（月曜〜日曜）の Gmail・Googleカレンダー・Google Drive 上の議事録や資料。
今週対応が必要そうな事項を1件ずつ抽出し、次の書式で書いてください。

# 通常業務

対象週：（今週の月曜 yyyy-MM-dd）（月）〜（日曜 yyyy-MM-dd）（日）
確認日：（今日 yyyy-MM-dd）

## 1. 件名
- 情報源：
- 対応候補：
- 期限：
- 関係案件：
- 依頼内容：
- 会議・予定との関係：
- 要確認事項：

ルール：
- 推測で埋めない。取得できない期限は「要確認」、判断できない点は要確認事項に書く。
- 保存後、ファイル名・保存先・件数を報告する。

付録B　週間タスクを作る指示文 コピーしました

付録Aの処理後、プロジェクト「週間タスク」の新しいチャットへ送ります。

今週の週間分析をしてください。次を実際に開いて読み、推測で答えないでください。
- Google Drive「週間タスクボード」フォルダ内「週間タスク」フォルダ直下の「通常業務.md」「AI案件.md」
- スプレッドシート「週間タスクボード」の「タスク」シート（対象週と前週までの確定タスク・状態・実施結果・メモ・次回申し送り）

結果は次のJSON形式「だけ」で出力してください。説明文やコードブロック記号（```）は付けないでください。

{
  "対象週": "（今週の月曜 yyyy-MM-dd）",
  "見立て": "今週は何が中心の週か、負荷の偏り、前週からの未完了・持越しの状況（文章）",
  "コーション": ["期限接近・停滞・次工程不明・要確認などの注意", "..."],
  "タスク案": [
    {"タスク名": "...", "種別": "通常タスク", "曜日": "木", "優先度": 1, "重点": true, "例外情報": ""},
    {"タスク名": "...", "種別": "AI案件", "曜日": "", "優先度": 2, "重点": false, "例外情報": "", "AI案件現在地": "現在工程・工程状態・次にやる具体作業・現在の手番の要約", "案件キー": "AI案件.md に記載された TASK_CURRENT.md の場所"}
  ]
}

ルール：
- 「種別」は 通常タスク または AI案件。AI案件.md の案件は AI案件、通常業務.md の事項は 通常タスク。
- 「曜日」は 月・火・水・木・金 のどれか。複数日に分けて取り組む場合は ["月","火","水"] のように配列で書く（1タスクは1件のまま。曜日ごとに同じタスクを複製しない）。決められない場合は空文字 ""。
- 「優先度」は1以上の整数（1が最優先）。「重点」は true／false（今週の重点は3〜5件が目安）。
- 「例外情報」は通常は空文字 ""。区分：内容 の形で、区分は 要確認／不一致／チャット未確認／取得失敗 のみ。
  AI案件.md で「情報源整合：不一致」の案件は「不一致：内容」、「情報源整合：要確認」の案件は「要確認：内容」をそのまま引き継ぐ。
  情報源整合が「一致」で、要確認欄が「チャット未確認」や「古い資料・台帳内の古い記載」の注記だけの案件は、例外情報にしない（2026-10-11 ユーザー決定：台帳の最新とDriveが一致すればチャット未確認でも確認済み）。
- 「AI案件現在地」は 種別がAI案件 の場合だけ書く。
- AI案件の前回とのつながり（2026-10-11）：AI案件.md の各案件について、「タスク」シートの前の週以前で同じ「案件キー」のいちばん新しい行（AI案件現在地・現在地確認日時・最新取得日時・最新取得結果・最新取得現在地・次回申し送り）と比べる。
  - AI案件.md の「台帳の最新記録日」が、その行の「現在地確認日時」または「最新取得日時」より古い場合は、AI案件.md の現在地を採らない。「AI案件現在地」を空文字 "" にし（保存時に前の週の値が引き継がれる）、「例外情報」に「要確認：週次巡回の記録（台帳の最新記録日）が前回の記録（日時）より古い」と書く。
  - それ以外は AI案件.md の現在地を採る。前の週の「次回申し送り」は見立て・コーションで触れる。
- 「案件キー」は 種別がAI案件 の場合だけ書く。AI案件.md のその案件の「TASK_CURRENT.md：（ファイルの場所）」を一字も変えずにそのまま書く。場所が書かれていない（「なし」など）場合は "案件キー" を書かない。タスク名や他の案件から推測して書かない。
- 「タスク」シートで対象週（今週の月曜）の行は、すでに確定済みのタスク。これと同じ通常タスクはタスク案に出さない（新規候補として再生成しない）。
- AI案件.md の案件は、対象週に同じ案件の行がすでにあっても、必ずすべてタスク案に出す（2026-10-12 ユーザー決定：巡回を取り直したら、今週の表の現在地・例外情報も取り直した結果に直す）。タスク名は対象週のその行と同じ名前にし、案件キーを必ず書く。週間画面で読み込むと、今週の行は「分析結果で更新」になり、確定して保存で AI案件現在地・例外情報が書き換わる。
  その状態・実施結果・メモ・次回申し送りは、見立て・コーションで触れてよい。
- 前週以前の行で状態が 次週候補・持越し・未着手・進行中 のものは、見立て・コーションで触れる。今週のタスク案に含める場合は、対象週に同じタスク名の行がすでにないことを確認してから出す（ある場合は出さない）。
- 期限・担当・次工程などを推測で埋めない。読めなかったファイルがある場合は、コーションに「取得失敗：ファイル名」と書く。

付録C　朝ブリーフを作る指示文 コピーしました

平日の自動処理後、プロジェクト「週間タスク」の新しいチャットへ送ります。

今日の朝ブリーフを作ってください。次を実際に開いて読み、推測で答えないでください。
- Google Drive「週間タスクボード」フォルダ直下の「朝情報.md」
- Google Drive「週間タスクボード」フォルダ直下の「AI案件_日次現在地.md」
- スプレッドシート「週間タスクボード」の「タスク」シートのうち、今週（対象週＝今週の月曜）で「削除済み」が空欄の行（タスクID・タスク名・種別・曜日・状態・優先度・重点・実施結果・メモ・次回申し送り・例外情報・AI案件現在地・案件キー）
「週間タスク」フォルダ（Obsidian Vault）の「通常業務.md」「AI案件.md」は読まないでください。

結果は次のJSON形式「だけ」で出力してください。説明文やコードブロック記号（```）は付けないでください。

{
  "日付": "（今日 yyyy-MM-dd）",
  "今日の一言": "今日はどんな一日か（短い見立て）",
  "今日の流れ": ["HH:mm 予定", "..."],
  "今日優先すること": ["今日の曜日に配置されたタスク・要対応メールのうち優先するもの", "..."],
  "気にかけておきたいこと": ["期限接近・要確認・不一致など", "..."],
  "もう片づいていること": ["今週のタスクで状態が完了のもの", "..."],
  "未完了・持越し": ["今週のタスクで未着手・進行中のまま気にすべきもの、状態が持越し・次週候補のもの", "..."],
  "AI案件現在地": [
    {"案件キー": "（AI案件_日次現在地.md のその案件の TASK_CURRENT.md の場所）", "taskId": "（タスクシートで案件キーが同じ行のタスクID）", "案件名": "...", "取得結果": "確認済み", "現在地": "確認できた現在地", "取得日時": "yyyy-MM-dd HH:mm", "内容": ""}
  ]
}

ルール：
- 項目が無い場合は空配列 [] にする。
- 「今日の流れ」は朝情報.md の今日の予定を時刻順に並べる。
- タスクの状態は「タスク」シートの値をそのまま使い、推測で変えない。
- 状態が「保留」のタスク（今週は何もせず、来週以降に実施する）は、状態だけを理由に「今日優先すること」に入れない。
- 例外情報（要確認・不一致・チャット未確認・取得失敗）があるタスクは「気にかけておきたいこと」に区分ごと書く。
- 朝情報.md に「取得失敗」がある場合、または朝情報.md・タスクシートを読めなかった場合は、「気にかけておきたいこと」に「取得失敗：内容」と書く。
- 「今日の曜日に配置されたタスク」は、タスクシートの「曜日」（「月,火,水」のように複数のことがある）に今日の曜日を含むタスク。
- 「AI案件現在地」は、AI案件_日次現在地.md に載っている案件ごとに1件書く。
  - 「案件キー」は、AI案件_日次現在地.md のその案件の「確認元 - TASK_CURRENT.md：（ファイルの場所）」のうち、ファイルの場所（TASK_CURRENT.md で終わる部分）だけを一字も変えずに書く（追加改修④③：週次・日次で同じ識別）。場所のあとに続く括弧書き・取得経路・エラーなどの説明は「案件キー」に入れない（必要なら「内容」に書く）。場所が書かれていない場合は空にする。
  - 対象5案件の案件キーは次の固定値。これ以外の値（説明つき・表記ゆれ）を書かない。
    ・C:\Users\inamori240\Documents\machine-sales-system\tasks\TASK_CURRENT.md
    ・C:\Users\inamori240\Documents\機械販売事例アプリ\tasks\TASK_CURRENT.md
    ・C:\Users\inamori240\Documents\営業AIメモ\tasks\TASK_CURRENT.md
    ・C:\Users\inamori240\Documents\管理職AIメモ\tasks\TASK_CURRENT.md
    ・https://github.com/xxxinakenxxx-hash/Weekly-Tasks/blob/HEAD/tasks/TASK_CURRENT.md
  - 「taskId」は、タスクシートの「案件キー」列がその場所と同じ行のタスクIDを書く。同じ行が無い場合は空にする。案件名（タスク名）で対応付けない（推測しない）。
  - 取得結果・現在地・取得日時・内容は、AI案件_日次現在地.md の該当案件の記載をそのまま使う。現在地を推測で補わない。
  - 取得結果は 確認済み／要確認／不一致／取得失敗／チャット未確認 のいずれか。確認済みのときだけ現在地を書く。
  - AI案件_日次現在地.md を読めない場合、または取得日が今日でない場合は、全件を「取得失敗」とし、内容に理由を書く（前回の値を今日の現在地として書かない）。
  - 確認済み以外の案件は「気にかけておきたいこと」にも「区分：案件名／内容」で書く。取得失敗の案件を「確認済み」に変えない。
- JSONの書き方（2026-10-14：Windowsの場所でJSONが壊れたため）：
  - 文字列の中の「\」（Windowsの場所の区切り）は、JSONでは「\\」と2つ重ねて書く。例："C:\\Users\\inamori240\\Documents\\営業AIメモ\\tasks\\TASK_CURRENT.md"
  - 文字列の中の「"」は「\"」と書く。文字列の中で改行しない。
- 出力する前に、次をすべて確かめ、1つでも満たさなければ直してから出力する。
  - JSONとして読み込める（括弧・カンマ・引用符・「\」の重ね書きが正しい）。
  - 「日付」「今日の一言」「今日の流れ」「今日優先すること」「気にかけておきたいこと」「もう片づいていること」「未完了・持越し」がそろっている。
  - 「AI案件現在地」の各件の「案件キー」は、空か、上の固定値のどれか（TASK_CURRENT.md で終わり、説明が付いていない）。
  - 「取得結果」は AI案件_日次現在地.md の値のまま。確認済みの件には「現在地」と「取得日時」がある。
